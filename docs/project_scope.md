## Project
Use case #2 from the Week 2 handout: **Financial Document Intelligence Pipeline RAG**, built no-code with **Lyzr**.

## One-liner (Primer)
My RAG app helps **equity analysts and investors** answer **comparative financial and risk-disclosure questions** from **the FY2024–FY2025 10-K filings of Rumble, Reddit, and Nextdoor** in **a Lyzr chat interface** with **90% faithfulness**.

## Corpus
6 documents total — FY2024 and FY2025 10-K annual reports for three public "social sharing" platform companies. All three now line up on the same two fiscal years.

## Framework (per Week 2 handout, Part 1)

- **Use case**: Analysts ask cross-year and cross-company questions (revenue trends, user metrics, risk factors) via a Lyzr-hosted Q&A chat interface.
- **Corpus**: 6 SEC 10-Ks (HTML/PDF), English, SEC EDGAR as source of truth. See table above.
- **Ingestion + cleaning**: Pull filings from EDGAR, strip HTML/XBRL markup and boilerplate legal text, preserve financial statement tables intact. Done outside Lyzr — see `ingestion/` in the project folder.
- **Ingestion + freshness**: One-time static ingestion — these are annual filings, no refresh cadence needed for this project scope.
- **Chunking + embedding**: Compare fixed-size (~500 words, 50-word overlap) vs. section/topic-based ("semantic," split at 10-K Item boundaries, capped ~800 words/chunk) chunking strategies on the same corpus and query set. Embeddings generated by Lyzr's default embedding model (via provided Nebius credits) once chunks are uploaded — same embedding model used for both KBs.
- **Retrieve**: Lyzr vector store, top-k ~10. Lyzr's Configure panel offers Basic / MMR / HyDE retrieval types but no dedicated reranking model — **MMR is used as the practical reranking stand-in**, with this substitution called out explicitly in the report.

## Deliverable
Working financial RAG pipeline in Lyzr + a chunking strategy comparison report (fixed vs. semantic) + reranking impact discussion, run against a 15-question eval set (single-fact lookups, cross-year trends, cross-company comparisons, and 2 deliberately unanswerable questions to test the refusal path). Bonus: a chat interface so the class can query the pipeline directly — **Lyzr's own published-app links** (see below), not a custom Streamlit app.

**Scope decision (2026-08-23)**: the eval was originally planned as a full 2×2 (chunking × retrieval type, 4 conditions × 15 questions = 60 runs). Only 2 of the 4 conditions were actually completed — see Eval section below for why — and the remaining reranking comparison work was deliberately dropped. The report will present a chunking-vs-retrieval-type comparison across the two conditions actually run, with the incomplete 2×2 named as a methodology limitation rather than glossed over.

## Chat Interface for Class Sharing (Bonus Add-on)

**Decision reversed (2026-08-23): using Lyzr's own published-app links instead of a custom Streamlit UI.** Earlier assumption was that Lyzr's "Launch App" flow only offered visibility inside Lyzr's own marketplace, with no standalone shareable link — that assumption was wrong, or the product has since added one. Publishing an agent from Lyzr Studio's Playground (toggle to public) produces a direct URL usable by any logged-in Lyzr user, e.g. `https://studio.lyzr.ai/create-new-agent/<agent-id>?tab=playground&public=true`. This is simpler than standing up and hosting a separate app, so the custom Streamlit build was dropped in favor of it.

**Published links (both confirmed live, 2026-08-23):**
- **Fixed-Size-Agent** (Fixed-size chunking KB): https://studio.lyzr.ai/create-new-agent/6a89d97e0fdb3536018ada9f?tab=playground&public=true — page title confirms "Fixed-Size-Agent." (Initially mislabeled as Semantic-Agent when first shared — corrected after checking the actual page header in a screenshot.)
- **Semantic-Agent** (Semantic chunking KB, page titled "Semantic Chunking Agent"): https://studio.lyzr.ai/create-new-agent/6a89db5c4b07c8f6f2ea3902?tab=playground&public=true

Publishing both agents (rather than just one) lets the class explore the actual chunking-strategy comparison hands-on, which was the same motivation behind the dropped Streamlit agent-picker.

**Known limitations to note in the write-up**:
- These links require the visitor to be logged into Lyzr (`public=true` inside Lyzr's own domain, not a fully anonymous public page) — different from the original Streamlit plan, which would have worked for anyone with the link, no account needed.
- **Confirmed live on the published Fixed-Size-Agent link**: the same cross-turn session contamination flagged during eval logging (`lyzr/prompts.md`'s methodology notes, and Condition 4's Q12) reproduced in a real screenshot — a single session mixed together answers to three unrelated questions (Reddit net income, Reddit DAUq, Rumble advertising %), including reproducing the exact fabricated "86.0% advertising" figure from the earlier discarded Condition 1 test. Anyone using these published links should start a **New Chat** before each unrelated question, the same discipline used throughout the eval — worth stating explicitly wherever these links are shared with the class.

### Ingestion pipeline — run and verified on real data (2026-08-21)

All three steps run successfully end to end on Ranjith's machine:

1. `fetch_filings.py` — downloaded all 6 real filings into `data/raw/`. Required creating a local `.venv` first (`python3 -m venv .venv && source .venv/bin/activate`) due to macOS's PEP 668 externally-managed-environment restriction on system Python.

3. `chunk_filings.py` — chunked all 6 into both variants, with chunk filenames prefixed by filing slug (e.g. `rumble_fy2024_chunk_0001.txt`) to avoid collisions once all semantic chunks get flattened into one Lyzr upload batch. Actual chunk counts:

## Lyzr build — knowledge bases and agents (done)

- Two Knowledge Bases created: `basic_fixed_size` (6 full cleaned filings, Lyzr's native chunker) and a semantic KB (574 pre-split Item-boundary chunk files, uploaded individually — Lyzr's 5-file-at-a-time limit and lack of zip support meant all 574 were uploaded one by one).
- Two Agents created, `Fixed-Size-Agent` and `Semantic-Agent`, each attached to one KB. Identical Role/Goal/Instructions, embedding model, generation LLM (`gpt-5.4-mini`), temperature (~0.1–0.2) — only the attached KB differs. Full text in `lyzr/prompts.md`.
- **Methodology fix applied**: Lyzr Playground carries full conversation-thread history into each call even without the explicit "Memory" feature enabled. Fix: fresh Playground session before every one of the 15 questions, for every condition. Documented in `lyzr/prompts.md`.
- **Finding (2026-08-23)**: Lyzr appears to run backend memory processing (`lyzr_memory_process_completed` event observed) even when the agent's "Memory" feature is not explicitly enabled in the builder — contradicting the earlier assumption that Memory was fully off. Full detail and action items in `lyzr/prompts.md`.
- **Confirmed on the published links (2026-08-23)**: a real screenshot of the published Fixed-Size-Agent link showed the same cross-turn contamination live — see Chat Interface section above. This is a genuine risk for anyone using the class-facing links, not just an eval-methodology footnote.
- **Published, 2026-08-23**: both agents' Playground made public — see Chat Interface section above for the correct links (initial labeling had them swapped; corrected after checking each page's own title).

## Eval — originally a 2×2 design, actually completed as 2 of 4 conditions

15-question eval set (5 single-fact, 4 cross-year, 4 cross-company, 2 deliberately unanswerable) was planned against 2 chunking strategies (fixed-size / semantic) × 2 retrieval types (Basic / MMR, as the reranking stand-in) = 4 conditions, 60 runs total, logged in `docs/eval_results.md`.

**What actually happened**: Condition 1 (Fixed-size KB, Basic retrieval) ran as planned — 15/15, clean. When running what was intended to be Condition 2 (Fixed-size KB, MMR retrieval), the Lyzr Playground window actually had the **Semantic-Agent** selected rather than Fixed-Size-Agent — discovered only after all 15 answers were logged. So that data is really **Condition 4 (Semantic KB, MMR retrieval)**, and has been relabeled as such in `docs/eval_results.md`. **Conditions 2 (Fixed-size × MMR) and 3 (Semantic × Basic) were never run**, and — per project decision on 2026-08-23 — will not be run.

**Condition 1 (Fixed-size KB, Basic retrieval) — 15/15, complete.** 8 clean exact-match hits, 2 correct refusals on the unanswerable questions, 1 faithful-but-incomplete answer on a real retrieval gap (Q5), 1 partial-but-faithful answer on a deliberate metric-redefinition trap (Nextdoor WAU→Platform WAU, Q9 — the lead demo beat in `docs/demo_script.md`), 1 faithful refusal on an inconsistent retrieval (Q12). No hallucinations and no wrong answers stated with confidence anywhere in this condition.

**Condition 4 (Semantic KB, MMR retrieval) — 15/15, complete (relabeled from a mislabeled "Condition 2" run).** 8 clean exact-match hits, 2 correct refusals (Q15's refusal arguably the cleanest seen in the project), 1 faithful-but-incomplete answer on the same Nextdoor trap as Condition 1 (Q9), 1 faithful refusal on the same Rumble advertising-% retrieval gap as Condition 1 (Q5), 2 self-contradictory-headline answers where the computed numbers were correct but the opening sentence stated the wrong company/direction (Q8, Q11), and 3 genuinely wrong or unstable answers (Q4: wrong DAUq figure; Q7: wrong Reddit FY2025 net income, conflated with a different line item; Q12: after a session-contamination first attempt, a clean rerun produced a *different* wrong answer claiming Reddit had a net loss).

**Headline finding for the report**: Condition 1 had zero outright-wrong answers across 15 questions. Condition 4 had three, two of them on Reddit's FY2025 bottom line specifically — Q2, Q7, and Q12 in that single condition produced three mutually-inconsistent figures for the same fact (net income +$529.7M / +$162.7M / net loss -$484,276). Since chunking strategy and retrieval type both changed between these two conditions, this can't be cleanly attributed to either variable alone — the comparison report should present this finding with that caveat rather than as an isolated reranking-impact result.

**Open flag (not further investigated)**: Rumble-specific figures showed two internal inconsistencies within Condition 1 (FY2024 revenue: $91.41M in Q11 vs. $95.49M in Q1's saved retrieval log; FY2025 net loss: $54.22M in Q13 vs. $81.83M in Q6). This did NOT reproduce in Condition 4 — Q6/Q11/Q13 there consistently returned $95,488,190 and $81,830,362. Worth a one-line mention in the report as an open question, not worth further chasing given the scope cut.
